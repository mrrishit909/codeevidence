How a review moves

  1. Load a named fixture

    Choose Golden, Clean or Empty. Input is checked atomically: any schema error rejects the whole source and leaves nothing half-loaded.

  2. Run the rule pack

    Seven structural rules in ce-structural-1 run over every submission and every link. One good link never cancels a bad one.

  3. Open a finding

    Filter by rule or ID, then open the cited submission, association and document records exactly as supplied, read-only.

  4. Record a human decision

    Escalate to clinical review, confirm, dispute or defer, with a note of up to 2,000 characters. Decisions sit in a separate layer and never alter a finding.

  5. Export the trail

    JSON carries schema and rule versions, a SHA-256 of the input, the input snapshot, every finding and the reviewer layer. CSV neutralizes formula-leading cells.

Where it stops

It does

  • Check structure between fictional submissions, links and document records.
  • Show every source field it used, unchanged.
  • Show supplied status text as written. asserted_support and asserted_conflict come from the fixture; nothing is inferred.
  • Run entirely in the browser: no network calls, no account, no server.
  • Read only the bundled synthetic fixtures. The public demo has no file import.

It does not

  • Apply CMS or RADV rules, or give clinical, coding, legal or regulatory guidance.
  • Diagnose, assign codes, judge medical necessity or establish clinical support.
  • Calculate repayment or submit anything anywhere.
  • Provide HIPAA certification, privacy assurance or access control.
  • Verify where a record came from. Fixture provenance is this repository, nothing more.

Zero findings means structurally consistent, human clinical review required. It never means supported.
